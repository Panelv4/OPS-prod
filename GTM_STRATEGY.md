# Founder-led go-to-market · $0 media budget

**Objective:** learn whether a fixed-fee agency repeatedly uses the client→project→invoice handoff. Revenue target ₹100k MRR (~20 Growth workspaces) is a planning destination, not month-one expectation. Start with [India-based small web agencies](MARKET_OPPORTUNITY.md); reserve UK for a second experiment. No campaigns, scraped lists, paid ads, automated sending or public launch have been authorized.

| Stage | Founder A (engineering / solutions) | Founder B (discovery / operations) | Evidence and decision |
|---|---|---|---|
| Days 1–7: qualify pain | Rehearse the same 7-minute demo in a fresh synthetic workspace; time setup; log every point of confusion | After approval, request introductions via existing agency relationships, professional groups that allow research, or opt-in replies to educational posts. Ask about the last handoff before demo | Target 10 conversations over experiment, not guaranteed responses. Record independent repeated pain, workaround, buyer and veto; stop if interviews merely praise UI |
| Days 8–14: narrow the pilot | Fix highest observed blocker; preserve single release candidate and test before each demo | Offer 2–3 consenting teams a guided **synthetic-only** session; ask for a teammate next time | Observe unaided customer → project → invoice/entry + invite. A founder clicking all four steps isn't buyer activation |
| Days 15–21: test repeat use | Check retention/queue/role failures, no special-case hidden discounts or fake records | Ask champions to repeat a second engagement. Test monthly prices neutrally, record blocked approval/retention and local currency needs | Two unrelated teams returning with a teammate beats ten signups. If bookkeeping export is consistently missing, test a sample export before building an integration |
| Days 22–30: decision | Review data/privacy/settlement/backup gates and actual time to support a workspace | Summarize willing design partners, declined offers and reasons. Prepare honest comparison and directory drafts, not launches | Both founders decide iterate/narrow/stop. No paid pilot until operational/legal and sandbox gates pass. Public announcement requires separate approval |

**Channel order:** warm introductions → helpful answers in permitted agency communities → founder-authored workflow tutorial → opt-in demos. Publish neutral comparisons only after verifying current facts and clearly labeling sample screens. No mass cold reach-out. Defer Product Hunt/listings until the app, support and terms can withstand self-serve users. No purchased upvotes or incentivized reviews.

**Weekly scorecard (small denominators shown):** conversations requested with permission/completed; qualified buyer pain/total interviewed; demos/qualified; unaided activated/workspaces registered; same-cohort week-two and week-four return; feature requests by repeated problem; provider receipts, refunds and churn only when live; onboarding + weekly support minutes; actual operating cost. Capture redacted, consented notes. Use `npm run metrics` for aggregate product signals, not marketing attribution or proof of revenue. Funnel arithmetic for planning: if measured demo→pay later equals *p*, required qualified demos for 20 customers is `ceil(20/p)`, before churn. **p is unknown**. Don't replace it with a fabricated conversion rate.
