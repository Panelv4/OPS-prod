# Security register · local source review

Verified against the archive, not a report of incidents. No customer records or external targets were used. Methods are code inspection and expected-control tests on synthetic records, not attack instructions. See PRODUCTION_READINESS.md for the test environment. Residual risks below remain release gates.

### Supply chain / operational observations

- **S15 HIGH (development tooling), `package-lock.json`, ESLint/Next lint dependencies.** `npm audit --json` counts **14 high package entries**, including transitive parents, from the picomatch advisory [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf). Inspected installed paths through Next lint's `fast-glob`/`micromatch` and TypeScript import resolver's `tinyglobby`/`fdir`. Current `picomatch@4.0.7` is in the reported affected range. Potential availability impact for tools processing untrusted patterns, not evidence of a customer-data breach. **Open**: run lint only on trusted repo inputs in isolated, resource-bounded CI without secrets; monitor patched tooling and rerun full audit. Do not force-downgrade Next to satisfy the auditor.
- **S16 MEDIUM (development tooling), `drizzle-kit` → old `@esbuild-kit` → esbuild.** Four moderate package entries; `npm ls esbuild` identifies dev generator transitives, not the production migrator. Untrusted access to an affected dev server is the exposure of concern. Never expose Drizzle Studio/esbuild servers; use offline journal generation and reviewed SQL. **Open** pending compatible supported upgrade. `npm audit --omit=dev --json` returns 0 across severities on this lock. A separate production-only install served the HTTP/browser suites and ran the migrator/worker without `eslint` or `drizzle-kit`. This does not negate development/build-time risk.
- **S17 MEDIUM, `src/lib/automation.ts`, `app/api/automations`, UI.** Source review: a “test” action previously used an illustrative payload in the live tenant, and a generated approval could follow actions. Potential unwanted writes; no observed external delivery. **Fixed for new drafts**: preview returns step names only; approval is placed before effects when requested. Stored order is explicit; review old definitions before enabling. Fixture worker checks delay → approval → exactly one task, and failed step across worker restarts.
- **S18 INFORMATIONAL, tenant lists / metrics.** Some routes still aggregate after full-tenant reads. No benchmark at production row counts. At scale this can hurt latency/memory even without a demonstrated incident. Profile with synthetic load, paginate lists, move aggregations into SQL and alert on pool saturation before raising workspace limits. The search route now limits SQL matches per type.

- **S19 HIGH if the earlier local Compose credentials were promoted, `docker-compose.yml`.** Source review found the PG image bootstrap superuser DSN in both serving processes. This was a packaging risk, not an observed intrusion. Compose now gives the migrator only its DDL DSN and the web/worker only the runtime DSN. The new bootstrap and explicit table grants were exercised on native PG16; the catalog probe and restore checks confirm no role membership/elevation, schema creation, migration journal, table ownership, audit edits or truncate privileges for runtime. The full API/unit/integration suite passed under that identity. This does not add DB RLS or isolate web from worker. Test the **actual image** with the [Compose rehearsal](DEPLOYMENT_RUNBOOK.md), verify vendor-managed roles independently, and don't auto-adopt old privileged volumes.
