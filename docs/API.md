# API conventions and route index

The [audited inventory](../AUDIT.md#original-api-inventory) lists every original path/method and its entry gate. The following is the **current** contract for integration-sensitive changes; action schemas in `src/app/api/**/route.ts` are authoritative.

- Same-origin JSON. `opspilot_session` cookie only; no bearer header/localStorage fallback. Authenticated mutations require the current `x-csrf-token`. Refresh `/api/auth/me` after login, verification, password, workspace or membership changes. Cookie and CSRF are different credentials. Don't log either.
- Public `POST /api/auth/{register,login,password-reset}`: no tenant-data reads; login takes email/password only. Register queues a verification message. Recovery `step=request` returns the same message for an unknown/known address; `step=confirm` consumes the mailed code. No API returns a mail preview. `POST /api/auth/logout` requires CSRF. Read-only public `GET /api/health` returns 200 when the readiness query succeeds or sanitized 503 when the handler cannot query the schema. Invalid runtime config can prevent the handler from running at all. Health never migrates or seeds.
- `/api/workspace`: verified member for GET; invites and audit filtered. PATCH settings/role matrix/widgets/AI/switch/create/accept by action. `accept_invitation` accepts the signed-in user's mailed `inviteCode`; role comes from the invitation. Email must match; switches session. `/api/workspace/members` invites or changes/suspends member with delegation restrictions. Owners control billing and role policy.
- `/api/crm/customers/import` POST = `{csv,confirm:false}` for preview; pass the same CSV + `confirm:true` to commit. Tenant lock, max 200 rows and 64k chars, exact headers; duplicates skipped, not overwritten. See customer and lead routes for manual entry.
- `POST /api/projects` actions include `create_project`, `create_task`, `add_comment`, `log_time` (`projectId,workDate,minutes`). `/api/sales/invoices` accepts optional `projectId` for that customer. Finance entries may be allocated to a project. Project GET returns `loggedMinutes`; billed/due and net cash are `null` without the respective read permission. Workspace currency is fixed; minor units are 1/100 for the supported currencies.
- `/api/hrms` `create_employee` requires an explicit supported `jurisdiction` (`IN`, `US`, `GB`, `SG`, `AE`) and integer `taxRateBps` between 0 and 5000. Omitted inputs or unsupported profiles receive 400; a 0 rate is a deliberate input. Rates are for simplified estimates, not statutory filing. Legacy SQL defaults/records do not select a correct profile for migrated employees. Attendance defaults to the current UTC date/time when not supplied. Check-in starts at zero completed minutes; same-day checkout records the interval. Duplicate check-in/checkout cannot overwrite it, and HR-only absence marking cannot erase a check-in. No overnight or multiple-shift model. Payroll and customer payments are records only, not transfers.
- `/api/finance` legacy response names such as `netProfitCents` and `profitAndLoss` represent **posted cash movement**, not accrual profit. Reconcile to the accountant’s books.
- `/api/documents` GET list/current detail/download, POST create/new_version, DELETE current document and versions. All paths use tenant and visibility gates. Max 5 MiB decoded. Never treat a downloaded file as trusted executable content.
- `/api/notifications` GET/PATCH applies recipient, role, preferences and module scope; PATCH writes a receipt for the caller. `/api/search` returns at most 25 hits per queried entity before the combined result cap. `/api/ai` returns only caller/scope history; `confirm_action` acts on a stored pending action, not a client-supplied SQL command or decision about permissions.
- `/api/automations` POST drafts. PATCH approve/toggle/test_run (read-only preview), run_scheduled_sweep (enqueue), approve_execution (resume). A queued execution is **not** completion. See `workflow_executions` for state. UI deletion is not a dead-letter replay.
- `/api/billing` GET/POST owner only: POST `checkout` with `starter|pro|business`, or `portal`, returns a hosted test URL only when configured. No direct plan-change call. `/api/billing/webhook` POST authenticates **raw bytes** with Stripe signature, not cookies/CSRF. Uses separate test credentials. Browser redirect proves nothing about settlement.
- Expected failures: 400 invalid/foreign relation, 401 no valid session, 403 missing verification/permission/CSRF, 404 scoped record unavailable, 409 conflict/capacity, 413 oversized body, 415 wrong content type, 429 throttle, 503 readiness/config unavailable. Unexpected errors are generic. A 200 HTML shell at `/app/...` is not authorization; private data is fetched separately.
