# What can we show a five-to-thirty-person agency?

**Local** = backed by application/DB behavior; **partial** = defined boundary; **fixture** = exercised with fictional data or provider responses; **gated** = not a sellable feature. Status is not a promise of hosted reliability.

| Workflow | Status and evidence | Boundary / what not to sell |
|---|---|---|
| New workspace, invite, roles | Local. Registration chooses currency/region; email verification before modules; new or existing user may accept an email-bound invite. HTTP role tests; browser verification | Requires working SMTP and worker for a real user. No SSO, enterprise identity, or unattended ownership transfers |
| First client / lead | Local. Pipeline, contacts, communication notes, lead conversion; preview/confirm up to 200 CSV rows (`name,company,email`), skip duplicate email in workspace | No external lead enrichment, campaign platform, or arbitrary CSV field mapper |
| Project delivery | Local. Link client, team, tasks/comments, due dates, budget, manually entered spend, time entries, logged minutes. Browser check creates a client-linked project, logs 30 minutes, issues an invoice, records full payment and checks the project balance | Team names are not assignment-level ACLs; project module is workspace-wide. No automatic labor cost, utilization forecast or external client login |
| Sales and collections | Local. Quote/order/invoice, configurable per-line tax, order discount after line tax, print view, posted partial/full payments and refunds, internal reminder | Ledger records do not charge cards, wire money, send customer dunning, file GST/VAT or guarantee a compliant tax invoice. Print-to-PDF via browser |
| Engagement economics | Local/partial. Net recorded cash = linked posted credits minus linked posted debits; invoice face value/due and logged time shown with source permissions | Unallocated items and labor/overhead excluded; **not project margin**. Refunded invoice face value is not earned revenue. No currency conversion |
| Executive / finance | Local. Cash movement, open balances, category and date trends over recorded entries, cash reversals. Permission-gated dashboard and deterministic assistant | Not double-entry books or an accrual P&L. Use accountant-approved books as system of record; benchmark large tenants before launch |
| People | Local/partial. Directory, self attendance (one same-day interval, completed minutes at checkout) and leave, authorized review, salary/notes redaction, estimate runs and printable payslips | Employee creation requires an explicit supported estimate profile and withholding rate; there is no assumed 10% withholding. Flat illustrative rates, no live tax tables, bank rails or filing. No CA/AU payroll model. Country selection is not compliance |
| Inventory / procurement | Local. Catalog, stock movement, low-stock sweeps, PO approvals, receipt, recorded vendor payment. HTTP and conversion/cancel tests | No warehouse/serial fulfillment, accounting integration or actual bank transfer |
| Files | Local. 5 MiB cap, MIME/extension and shallow signature check, scoped attachments/downloads; current copy + version contents in Postgres. Owner/role/workspace scopes | No content execution, antivirus, external share links, S3 or raster OCR. Metadata history is not historical-version restore UI |
| Search / notices | Local. Tenant/permission-filtered search, bounded hits; current-user/role notifications with per-user receipts. Test shows one reader doesn't clear another's inbox | Not a public indexing service. Mail is a generic sign-in notice, not a record copy |
| AI | Local. Authorized SQL and deterministic responses; rates, monthly usage **units**, action confirmation. Text receipt parser requires review | Optional OpenAI product help only: explicit enablement, owner key, `help:` prefix. No customer-record prompt assembly, no tested external provider. Estimated units ≠ exact tokens or cost |
| Automations | Local/fixture. Stored event conditions, actions, delayed steps, approval and resume, retry and terminal failure, daily UTC sweeps. Duplicate keyed event and worker-restart tests | Natural-language builder uses rules, not a general agent. Daily sweep is not arbitrary cron/timezone scheduling. Approved actions may write; preview does not. A reminder is internal |
| Commercial subscription | Gated. Test-only checkout/portal, Stripe SDK signature verification, signed payload handler and local reconciliation fixtures; history + enforced seats/workflows/storage/AI | No merchant connected, hosted sandbox session, real receipt or charge. No annual plans, promo/proration, metered overages, Razorpay implementation or live MRR |
| Metrics / retention | Local. Tenant milestone set + UTC workspace/day/module counters; `npm run metrics` as operator, no cross-tenant browser API | Requests ≠ completed tasks. Historical cohorts start at instrumentation. No live churn/cost import or validated conversion rate |
| Infrastructure | Partial. Verified native production-only install, split-role PG migrations/restore, restricted web/worker, signup via loopback SMTP and HTTP/browser suite; one disposable Docker gate shared with CI | Docker/Compose runtime and remote CI not verified here; no production environment or SLA |

**What to build next?** A client portal crosses a new authorization boundary; first test whether a manually shared, redacted status summary is enough. Recurring billing of agency *clients* is separate from OpsPilot subscriptions: try a draft reminder, never auto-charge. Add cost-rate allocation only if teams already track hours and will maintain rates; prefer explicit project expenses now. Validate demand for one accounting export before two-way QuickBooks/Xero or chat integrations. Use three independent requests for the same workflow plus one willing design partner as a decision rule, not a claim of demand.
