# Environment setup

Use a separate DB, vault key, mailbox, origin and (only when authorized) gateway account/endpoint for local, test, staging and production. Never paste `.env`, cookies, email codes, provider responses or a DSN into support logs. Filled env files are ignored. `.env.example` is for native web/worker and `.env.compose.example` is for Compose; do not give a native Next process an admin/migrator dotenv file. Local tools use Node 22, npm 10 and PostgreSQL 16. Keep passwords URI-encoded. Production config is validated by Next instrumentation and by the worker, **not** embedded during static build. Check readiness, not just a process/port: a configuration error can leave Next listening but unable to serve the app.

| Setting | Purpose / constraint |
|---|---|
| `DATABASE_URL` | `postgresql://.../database` for the environment. Managed network with verified TLS outside loopback. Use migration owner for migration only, restricted DML role for web/worker. No request-time seed or schema push |
| `OPSPILOT_SECRET_KEY` | Separate random 32-byte hex secret (`openssl rand -hex 32`, save directly in secret manager/private file). App and worker must match. AES-GCM for BYO key/mail envelope and keyed limiter subjects; no DB-URL fallback. Do not replace without re-encrypting/draining existing data |
| `APP_ORIGIN` | Exact canonical origin, no trailing slash; HTTPS for nonloopback production runtime. Local example `http://localhost:3000`. Must match browser origin for JSON writes/hosted redirect |
| `POSTGRES_PASSWORD` | Compose bootstrap superuser only, not an app/migrator credential. Keep all three DB passwords and the vault key distinct |
| `OPSPILOT_MIGRATOR_PASSWORD`, `OPSPILOT_RUNTIME_PASSWORD` | `.env.compose` only: random hex strings (`openssl rand -hex 32` each); interpolated into different DSNs by service. Native web/worker need only the runtime DSN, not these extra variables. Never send the migration-owner DSN to them |
| `OPSPILOT_DB_NAME`, `LOCAL_APP_PORT`, `LOCAL_MAIL_PORT` | Optional Compose-only; defaults `opspilot`, `3000`, `8025`. Match the browser port to `APP_ORIGIN` for interactive use. The automated rehearsal sets its own name and ports |
| `TRUST_PROXY` | `0` unless an exclusive trusted ingress strips/replaces `X-Real-IP`; no client-supplied forwarding chain. Default `unknown` is a shared defensive throttle |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, `SMTP_USER`, `SMTP_PASS` | Verified transactional sender + STARTTLS (587) or TLS (465). Worker takes one due job per iteration; no stdout mailbox. Without transport local messages remain queued till expiry. Nonloopback production origin requires sender/host |
| `SMTP_LOCAL_SINK` | `1` only for explicit private `localhost`, `127.0.0.1`, or Compose `mailpit`, no TLS; never public. Compose supplies host/port/from and binds catcher UI to loopback |
| `BILLING_MODE` | `off` (default). Only other value: `stripe_test`. No live mode. Separate DB and external test account; never copy sandbox entitlements into production |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | Dedicated **test** API key and endpoint verification secret. SDK pinned, API `2025-02-24.acacia`. Secrets never in browser or commit |
| `STRIPE_PRICE_STARTER`, `_PRO`, `_BUSINESS` | Three exact `price_…` IDs, test USD monthly, one product line/quantity 1, amounts match `src/lib/plans.json`. `_PRO` = Growth, `_BUSINESS` = Scale. Only set in approved test environment |
| `STRIPE_PORTAL_CONFIG` | Test customer portal config. Permit catalog prices only, no trial/coupon/proration or immediate unpaid upgrade. Test scheduled change and cancel-at-period-end policy before showing customers |
| `ENABLE_EXTERNAL_AI` | `0` by default. `1` permits an owner to choose OpenAI and store a workspace-encrypted BYO key. Only the text after `help:` is intended for egress; never include business data. No env unlock for OCR/S3/Razorpay |
| `TEST_BASE_URL`, `CHROMIUM_PATH`, `RESTORE_DATABASE_URL` | Fixtures/browser and independent restore target only; see test and backup procedures. Not production secrets for the web process |

### Native dev (empty database)

1. Provision a dedicated PG16 database/credentials. The reference [first-init SQL](scripts/postgres/init-roles.sql) is for a **new, dedicated cluster/DB**, run by a DBA with `psql -X -v ON_ERROR_STOP=1` against that DB, `POSTGRES_PASSWORD` and two different random `OPSPILOT_*_PASSWORD` values supplied privately. It refuses system DBs, existing data/roles and reused credentials. It is not a managed-host migration or password rotation script. Prefer the [Compose runbook](DEPLOYMENT_RUNBOOK.md) to provision the complete local stack automatically.
2. `npm ci`. In a one-shot private migration shell, set `DATABASE_URL` to the migration-owner DSN and run `npm run db:migrate -- --grant-runtime` twice. Exit that shell. In a **separate** web/worker environment, use an ignored, mode-0600 `.env` from `.env.example` with the runtime DSN, vault and app origin. Never run migration as the serving login. `npm run dev` and, in another runtime-only terminal, `npm run worker`. For native dev mail use a private loopback SMTP sink, `SMTP_FROM`, the sink port and `SMTP_LOCAL_SINK=1`. A disposable legacy single-login developer DB may use the plain migrator without the grants flag; that is not evidence of role separation and must not be promoted.
3. Visit `/demo` to inspect the product without credentials, or register a synthetic address, retrieve verification **in the private catcher UI**, enter it on the verification screen. Do not copy production outbox data into a test mailbox. Configure currency at registration, review tax label/rates, then follow dashboard setup.
4. Historical seed is optional, guarded by `OPSPILOT_SEED_DEMO=1`, a separate `*_demo` DB and non-production process. Not required for the UI sample or any test. Never use or publish a shared demo account. Don't set up secrets merely to make a demo look live.

### Release test

Build with `npm run lint && npm run typecheck && npm run build`. Start with `npm run start -- -H 127.0.0.1` using loopback `APP_ORIGIN`/`TEST_BASE_URL` and migrated `*_test`. **Pause the background worker for the HTTP fixture suite** (it reads undelivered encrypted test messages). Export test env to the shell; `npm test`, `CHROMIUM_PATH=/path/to/compatible/chromium npm run test:browser`, `npm run worker -- --once`, `npm run metrics`. Tests create synthetic workspaces; use fresh DBs for independent runs. Test code never needs an email, AI or payment provider credential.

For a fresh split-role `*_test` DB on loopback, `node tests/ops-rehearsal.mjs acl` checks effective DB privileges without modifying data. Optional end-to-end native mail gate: use a dedicated **empty** `opspilot_packaging_test` DB and its loopback web server, no continuous worker, matching runtime-only environment, `BILLING_MODE=off`, `ENABLE_EXTERNAL_AI=0`, no SMTP credentials and no Stripe key. `node tests/ops-rehearsal.mjs native-mail` starts an ephemeral private SMTP sink, runs separate one-shot worker processes around a signup, verifies the captured message and imports a fictional contact. It refuses reuse. This is not the Docker/Mailpit test or a deliverability test.
