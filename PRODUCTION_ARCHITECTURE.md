# Proposed first-region architecture · not provisioned

**Choose one always-on Node web service + one small always-on worker + private managed PostgreSQL 16 in one region.** Render is the costed candidate, not an approved supplier. Choose region, DPA and support access after the primary-market interviews. Don't start with multi-region replication, Redis, Kubernetes, or blob storage just because env names existed in the archive.

```
Browser ─ HTTPS ingress (trusted TLS, request limits) ─ Next web ─┐
Signed Stripe test webhook ─ bounded raw body ─ reconciliation ───┤
                                                    private PG16 ├─ encrypted backups → independent account/region after review
Worker ─ daily sweep / workflow checkpoint / outbox claim ───────┘
  └─ TLS SMTP relay → verified recipient
Optional owner-enabled help: → OpenAI (no DB facts/history)
```

- One deployable Node image with separate commands for web, worker and one-shot migrator. Fonts local, stateless web replicas, same region/DB pool and vault key. Compose's persistent PG volume and local Mailpit are **development substitutes**, not the production topology. Never expose PG, worker, debug tools, or Mailpit to the web.
- Each process has a `pg.Pool` (max 8): budget roughly `8 × (web instances + workers) + migrator + operator headroom`. Verify against managed connection limits. Start with one of each; monitor query p95, active/idle/waiting connections, deadlocks, storage and CPU before scaling. SQL constraints guard references; app permissions guard reads; no RLS claim.
- Jobs live alongside the write they depend on. Workers claim via `FOR UPDATE SKIP LOCKED`, commit each local workflow step/checkpoint together, and use unique event keys for sweeps. SMTP can succeed just before a process dies: at-least-once, stable Message-ID, single-use auth codes, **not exactly-once delivery**. Retry/dead-letter states must be monitored. Don't promise exact cron time; daily sweep is UTC and catches up on polling.
- Compose separates bootstrap, migration and serving identities; native PG and the remote container gate both checked the restricted login. Web + worker share `opspilot_runtime` (reviewed DML, no schema creation, `TRUNCATE`, journal access or audit UPDATE/DELETE); `opspilot_migrator` owns migrated tables and can apply grants. Provision an independently scoped backup role and verify all managed-host grants before pilot. App uses SQL to manage its own non-audit business rows; RLS would be a separate migration with connection-context tests. Vault encryption is for *selected secrets*, not all DB rows. Require provider storage encryption, managed TLS, off-provider backup encryption/escrow and access review.
- **Files decision:** keep private versioned bytes in PG for bounded pilots (5 MiB/file). Logical payload quotas are not physical DB sizes: base64 and a duplicated current copy plus WAL/backups increase cost. Watch version growth, restore time and actual disk. Revisit when projected disk or restore window exceeds budget. Future interface: `putVersion/readVersion/purgeVersion` with server-generated tenant/object/version keys, range/auth checks **before** reads, private bucket, encryption/version policy, short-lived scoped downloads, malware quarantine, checksum + length verification. Stage write → metadata transaction → orphan sweeper; dual-read by storage kind, migrate existing records with checksum and rollback. No S3 adapter/credentials in this release.
- **Observability to provision:** HTTPS `/api/health` externally; separate worker heartbeat and age of oldest eligible job (health doesn't cover worker); aggregated 5xx/latency, migration version, bounced/failed mail, webhook failures/lag, PG locks/storage, backup age/restore exercise. Error collector with route-template/status/error class only; strip request/response bodies, SQL args, URLs with queries, auth headers, names, emails and IDs that identify individuals. Synthetic canary under a designated test tenant only. Alert both founders; acknowledge/escalate offline. No vendor telemetry installed or SLO demonstrated.
